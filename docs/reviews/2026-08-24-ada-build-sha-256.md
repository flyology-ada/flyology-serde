# Ada build identity SHA-256 review

## Scope

The future Ada build-identity verifier must attest the JSON and SHA2 dependency checkouts before the production
generator links them. Its digest implementation therefore cannot depend on the SHA2 checkout that it is evaluating.
This change adds a nonallocating incremental SHA-256 implementation inside the offline generator source tree and a
focused executable test. It does not mint a generator identity, add an Alire build action, change the installed
executable, or expose an identity command-line option.

The context is invalid until `Initialize`. Input accepts arbitrary Ada bounds and exact octets, and the cumulative
whole-byte length cannot exceed `Interfaces.Unsigned_64'Last / 8`. Overflow and update-after-finalization latch
failure. `Finish` is one-shot and publishes its digest only after the complete final block succeeds; every rejected
finish preserves the caller's prior digest.

## Review cycles

The generator-identity architecture review found no P0 issue. Its remaining production-wiring P1s are explicit user
authority for the public identity option and tracked action ceilings; this policy-free implementation does neither.
The reviewer required normative SHA evidence before the implementation may mint identities.

The independent change review found one P1: a default-constructed zero context could initially be used without the
SHA-256 initial vector. An explicit initialization latch now rejects and poisons uninitialized update or finish, and
direct tests prove digest preservation. The same review requested two P2 fixes: the visible state-machine contract
is now documented in the specification, and tests cover exact final-byte acceptance followed by rejection of the
next byte plus a null, non-1-based stream array. The narrow fix re-review reports P0 none, P1 none, and P2 none.

## Verification

- Standard empty, `abc`, and NIST multi-block known-answer vectors pass.
- Padding transitions at 55, 56, 63, 64, and 65 bytes pass; the values were independently cross-checked with
  Python's `hashlib` and OpenSSL before being recorded.
- Every two-fragment split of a 65-byte input, a million-byte incremental vector, binary NUL/high-bit octets,
  arbitrary lower bounds, and null input pass.
- Uninitialized use, repeated finish, update after finish, exact total-length capacity, and one-byte overflow have
  direct failure and output-preservation checks.
- A forced warning-enabled GNAT 16 build, the focused executable, and the complete generator smoke suite pass.
- `git diff --check` and the explicit 110-column scan pass. `gnatformat` was invoked through the owning test project,
  but the selected host and Alire toolchains do not provide it; compiler style checks remain enabled and pass.

The existing JSON/SHA2 Git-tree content digests will become additional end-to-end known answers when the bounded Git
reader is implemented. Until then this package is cryptographic infrastructure only and is not identity authority.
